Курсовий проєкт — це логічне завершення навчання та повноцінне production-ready IoT-рішення, побудоване за модульним принципом. Протягом курсу ви розроблятимете окремі компоненти цієї системи у межах домашніх завдань, а у фіналі — об’єднаєте їх у єдину екосистему, додасте просунутий функціонал та захистите свій проєкт.

Технічні вимоги до компонентів

1. Апаратна частина та Edge-логіка (Wokwi / ESP32)

Пристрій (ESP32):

1. Зчитує температуру, вологість та освітленість раз на 60 секунд.
2. Публікує телеметрію JSON на топік iot-course/<student_name>/telemetry з QoS 1.
3. Підписаний на iot-course/<student_name>/commands/led для керування світлодіодом.
4. Кнопка (з debounce) — миттєво надсилає поточні показники та публікує подію manual_trigger на iot-course/<student_name>/events.
5. Між циклами вимірювань — Deep Sleep на 60 секунд.
6. Підтримує OTA через AWS IoT Jobs.
7. Експоненційний retry при втраті Wi-Fi/MQTT (1с, 2с, 4с, 8с, max 30с).

Формат JSON-телеметрії

{
  "device_id": "esp32-<student_name>",
  "timestamp": 1730800000,
  "temperature": 23.5,
  "humidity": 47.2,
  "light_level": 612,
  "firmware_version": "1.0.0",
  "uptime_sec": 3600,
  "free_heap": 234567
}


---

2. Хмарна інфраструктура (AWS IoT Core)

AWS IoT Core: приймає дані від пристрою через MQTT/TLS за допомогою X.509 сертифікатів та Policy за принципом найменших привілеїв. Використовує три IoT Rules: 

* телеметрія йде у DynamoDB таблицю iot_telemetry, 
* події кнопки — в окрему таблицю iot_events, 
* вихід температури за межі (> 28 або < 15) викликає запис у CloudWatch Logs.

---

3. Бекенд-сервіс (FastAPI)

Бекенд (FastAPI): взаємодіє з базою даних та хмарою, надаючи п'ять ендпоінтів:

Column 1	Column 2	Column 3
Endpoint	Метод	Опис
/sensors/latest	GET	Повертає останній актуальний запис метрик із DynamoDB.
/sensors/history?hours=N	GET	Повертає історією за $N$ годин (максимум 24 години) для побудови графіків.
/events?limit=N	GET	Повертає список останніх $N$ подій натискання кнопки (manual_trigger).
/actuators/led	POST	Приймає JSON команди і публікує MQTT-повідомлення в AWS IoT Core для увімкнення/вимкнення LED на пристрої.
/health	GET	Перевірка працездатності самого API-сервісу.


---

4. Візуалізація та керування (Grafana)

Дашборд у Grafana підключається до FastAPI як до джерела даних (через JSON API datasource) та оновлюється в реальному часі.

* Панель 1 (Time series): графік коливання температури та вологості за останні 6 годин.
* Панель 2 (Gauge): стрілочний або радіальний індикатор поточної освітленості з кольоровими зонами (наприклад: зелена — норма, червона — темно).
* Панель 3 (Stat): картки з останнім часом синхронізації (timestamp) та часом безперервної роботи пристрою (uptime).
* Панель 4 (Table): таблиця з логом останніх 10 подій натискання фізичної кнопки.
* Також опційно — зворотний зв’язок: інтегрована кнопка (або окрема веб-сторінка), яка через API-endpoint POST /actuators/led надсилає команду {"action": "set_led", "value": "on"} у хмару, змушуючи світлодіод на ESP32 фізично засвітитися.

---

5. Вимоги до безпеки та OTA

* Безпека: використання Mutual TLS для MQTT, обмеження топіків через AWS Policy, сертифікати в .gitignore та авторизація FastAPI через IAM-ролі або змінні середовища.
* OTA: обов'язкове поле firmware_version у кожному payload та один задокументований цикл оновлення прошивки через AWS IoT Jobs з версії 1.0.0 до 1.1.0 (з внесенням однієї видимої зміни в код).

Що входить у фінальну здачу проєкту (Критерії оцінювання)

Для успішного захисту курсового проєкту студент має надати GitHub-репозиторій, який містить:

1. Код прошивки (PlatformIO): чистий код для ESP32 з розділенням на логічні модулі, налаштованим дебаунсом, режимом сну та реалізованим клієнтом OTA.
2. Код бекенду (FastAPI): працюючий Python-додаток із налаштованими ендпоінтами та логікою AWS SDK (boto3).
3. Файл README.md: детальна документація проєкту:
* Архітектурна діаграма системи.
* Інструкція з розгортання бекенду та налаштування AWS IoT Policy/Rules.
* Скріншот дашборду Grafana з реальними даними.
* Скріншот таблиці DynamoDB (мінімум 5+ успішних записів телеметрії).
* Скріншот логів CloudWatch, що підтверджує роботу алармів температури.

4. Демонстраційне відео: коротка демонстрація (до 2 хвилин) роботи системи: зміна даних у Wokwi -> оновлення графіку в Grafana -> натискання кнопки в Grafana -> реакція світлодіода на схемі Wokwi.
